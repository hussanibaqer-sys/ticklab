TickLab v1.13.0.120 — Drawing Interaction Lock-State Fix

ROOT CAUSE
- The four remaining failures shared one gate: global Lock All Drawings.
- A stale saved Lock All value could be restored while the selected-object quick toolbar still displayed only the individual drawing lock state.
- Result: drawings looked unlocked/selected, but whole-object drag, A/B/C anchor drag, middle-click remove, and quick-menu Remove were all silently blocked.

FIX
- Global Lock All is no longer restored from a stale previous session.
- Selecting any real drawing tool clears stale global Lock All before construction.
- Direct image placement also clears stale global Lock All.
- Individual drawing IsLocked flags are NOT changed. Explicitly locked drawings remain protected.
- The user can still explicitly enable Lock All during the current session.

PRESERVED
- v1.13.0.118 global drawing renderer is not changed.
- v1.13.0.119 one-select -> one-draw behavior is preserved.
- Blank-chart left-click deselection is preserved.
- Drawing Inspector deletion remains preserved.
- Middle-click delete handler, quick-menu owner resolution, body-drag and anchor-drag implementations are retained; this fix releases the stale gate that blocked them.
- Callout tail geometry from v1.13.0.119 is unchanged.
- No individual drawing-folder geometry/settings were modified.
